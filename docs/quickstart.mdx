## Prerequisites

Before you begin, install the following:

- **Python 3.12+** ([python.org](https://www.python.org/downloads/))
- **Docker** and **Docker Compose** ([docs.docker.com](https://docs.docker.com/get-started/))
- **Git** ([git-scm.com](https://git-scm.com/))
- **uv** package manager ([docs.astral.sh/uv](https://docs.astral.sh/uv/getting-started/installation/))

## Choose your path

<Tabs>
  <Tab title="Manager (recommended)">
    The Manager path starts the full platform: PostgreSQL, the FastAPI backend, and the React admin UI.

    <Steps>
      <Step title="Clone and configure">
        ```bash
        git clone https://github.com/Idun-Group/idun-agent-platform.git
        cd idun-agent-platform
        cp .env.example .env
        ```
      </Step>
      <Step title="Start the platform">
        <Note>Make sure the Docker daemon is running before you proceed.</Note>

        <Tabs>
          <Tab title="Production (pre-built images)">
            ```bash
            docker compose up -d
            ```
          </Tab>
          <Tab title="Development (build from source)">
            ```bash
            docker compose -f docker-compose.dev.yml up --build
            ```
          </Tab>
        </Tabs>

        Both start PostgreSQL, the Manager API, and the web UI.

        ![Idun login page](/images/ui/login.png)
      </Step>
      <Step title="Create an agent">
        Open [http://localhost:3000](http://localhost:3000) in your browser.

        Log in (if you have not configured an auth provider yet, press **Login** to skip). You land on the agent dashboard.

        ![Agent dashboard](/images/ui/agents-list.png)

        Click **Create** to launch the 3-step wizard. Select your framework (LangGraph or ADK), configure framework-specific settings, then review and save.
      </Step>
    </Steps>
  </Tab>

  <Tab title="CLI">
    The CLI provides an interactive TUI to configure and run a standalone agent without the Manager.

    <Steps>
      <Step title="Install the engine">
        ```bash
        pip install idun-agent-engine
        ```
      </Step>
      <Step title="Launch the interactive setup">
        ```bash
        idun init
        ```

        The TUI walks you through agent configuration: framework, memory, observability, guardrails, and MCP servers. When you finish, it saves the config and starts the agent server.
      </Step>
      <Step title="Verify the agent is running">
        ```bash
        curl http://localhost:8008/health
        ```

        Open [http://localhost:8008/docs](http://localhost:8008/docs) to see the API documentation.
      </Step>
    </Steps>
  </Tab>

  <Tab title="Manual">
    Use this path if you want full control over the configuration file.

    <Steps>
      <Step title="Install the engine">
        ```bash
        pip install idun-agent-engine
        ```
      </Step>
      <Step title="Create a config file">
        Save the following as `config.yaml` in your project directory. Update `graph_definition` to point to your agent file and variable.

        ```yaml config.yaml
        server:
          api:
            port: 8008

        agent:
          type: "LANGGRAPH"
          config:
            name: "my-agent"
            graph_definition: "./agent.py:graph"
            checkpointer:
              type: "memory"
        ```

        <Info>
          The `graph_definition` value follows the format `path/to/file.py:variable_name`. The variable should be a `StateGraph` (recommended) or `CompiledStateGraph`. The engine compiles it with the configured checkpointer.
        </Info>
      </Step>
      <Step title="Start the agent">
        ```bash
        idun agent serve --source file --path config.yaml
        ```
      </Step>
      <Step title="Verify the agent is running">
        ```bash
        curl http://localhost:8008/health
        ```
      </Step>
    </Steps>
  </Tab>
</Tabs>

## Minimal LangGraph agent example

If you do not have an agent file yet, create `agent.py` alongside your config:

```python agent.py
from langgraph.graph import StateGraph, MessagesState

def chatbot(state: MessagesState):
    from langchain_openai import ChatOpenAI
    model = ChatOpenAI(model="gpt-4o-mini")
    return {"messages": [model.invoke(state["messages"])]}

graph = StateGraph(MessagesState)
graph.add_node("chatbot", chatbot)
graph.set_entry_point("chatbot")
graph.set_finish_point("chatbot")
```

<Warning>
  This example requires the `OPENAI_API_KEY` environment variable. Export it in your shell or add it to your `.env` file before starting the agent.
</Warning>

## Switching to Postgres

The standalone runtime ships with SQLite as the default database for quickstart and demo. For production, switch to Postgres. SQLite's trace-storage ceiling is around 10k traces before the list view starts to lag. <!-- VERIFY: 10k trace ceiling sourced from tasks/trace-feature-08-05-2026/13-sizing-perf.md and 18-postgres-throughput-probe.md; rerun probe before each release. --> The trace UI shows a permanent banner reminding operators of this when SQLite is the active backend.

To switch:

<Steps>
  <Step title="Provision Postgres 15+">
    Provision a Postgres 15 or newer database. Make sure the `pg_trgm` extension is available, used for free-text trace search.
  </Step>
  <Step title="Set DATABASE_URL">
    ```bash
    export DATABASE_URL="postgresql+asyncpg://user:pass@host:5432/dbname"
    ```
  </Step>
  <Step title="Run migrations">
    ```bash
    idun setup
    ```

    Alembic creates the trace tables with monthly partitioning, plus the standard standalone admin tables.
  </Step>
  <Step title="Restart the standalone runtime">
    ```bash
    idun serve
    ```
  </Step>
</Steps>

Postgres unlocks 5–8k spans/sec sustained write (Linux production floor) versus 1k spans/sec on SQLite, plus richer free-text search and bounded read latency at scale. <!-- VERIFY: span/sec figures sourced from tasks/trace-feature-08-05-2026/18-postgres-throughput-probe.md (asyncpg copy_records_to_table benchmark); rerun probe before each release. -->

### Trace-store environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `IDUN_TRACE_RETENTION_DAYS` | `14` | How many days of traces to keep before dropping. On Postgres, expired monthly partitions are detached and dropped. On SQLite, a scheduled `DELETE` runs. |
| `IDUN_TRACES_INPUT_VALUE_MAX_BYTES` | `65536` | Per-attribute byte cap before truncation. Lower this on heavy-payload deployments to recover throughput, or raise it to keep more raw input/output. |
| `IDUN_PRICES_REFRESH` | `false` | When `true`, the cost calculator fetches the LiteLLM model-prices snapshot at boot (5 second timeout, snapshot fallback). Default uses the vendored monthly snapshot. |
