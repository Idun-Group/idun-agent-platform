Google ADK (Agent Development Kit) is Google's framework for building Gemini-powered agents. Idun Engine wraps ADK agents as production services with AG-UI streaming, guardrails, and observability.

<Tip>
  Want to start from working code? The [agent templates](/templates) include ADK examples for tool calling and structured I/O.
</Tip>

## Create an ADK agent

Set `agent.type` to `ADK` and provide the agent definition path and `app_name`:

```yaml config.yaml
server:
  api:
    port: 8000

agent:
  type: ADK
  config:
    name: "my-adk-agent"
    agent: "./agent.py:root_agent"
    app_name: "myagent"
```

The `agent` field is a file path of the form `<path/to/file.py>:<variable_name>`. The ADK adapter resolves it with `importlib.util.spec_from_file_location`, so the value must point at a real `.py` file (relative or absolute). Module-dotted notation (`my_pkg.agent:root_agent`) is not supported.

Install and run:

```bash
pip install idun-agent-engine google-adk
idun serve
```

The first boot reads `config.yaml`, seeds the DB, and serves the chat UI at `http://localhost:8000/`. After that you can edit the agent through the admin panel at `/admin/agent/` and the running engine hot-reloads on save.

<Warning>
  `config.yaml` only seeds rows that are missing. Once an agent row exists in the DB, subsequent edits to the YAML are ignored. The admin panel at `/admin/agent/` is the runtime source of truth. To re-seed from YAML you must clear the relevant rows (or, for a fresh start, delete the SQLite DB) and re-run `idun setup`.
</Warning>

For engine-only mode (no DB, no admin), use `idun agent serve --source file --path config.yaml` instead.

## Write your agent code

Create an ADK agent at the file path you referenced in `config.yaml`:

```python agent.py
from google.adk.agents import Agent

root_agent = Agent(
    model="gemini-2.5-flash",
    name="weather_agent",
    description="An agent that answers questions about the weather.",
    instruction="You are a helpful weather assistant. Answer questions about weather conditions.",
)
```

<Note>
  If you use Vertex AI models, authenticate with `gcloud auth application-default login` before running the agent.
</Note>

### The `agent` field

The value is `<path>:<variable>`:

- **Path**: a file path to a Python file, relative to the working directory or absolute (e.g., `./agent.py`, `src/agents/weather.py`)
- **Variable name**: the `Agent` instance exported from that file (e.g., `root_agent`)

LangGraph's `graph_definition` accepts both file paths *and* dotted module paths; the ADK adapter accepts file paths only.

## Adding MCP tools

To wire MCP servers registered in `config.yaml` (or the admin panel) into the agent, pull them in with `get_adk_tools()` and pass them to the `Agent` constructor:

```python agent.py
from google.adk.agents import Agent
from idun_agent_engine.mcp import get_adk_tools

root_agent = Agent(
    model="gemini-2.5-flash",
    name="weather_agent",
    description="An agent that answers questions about the weather.",
    instruction="You are a helpful weather assistant. Answer questions about weather conditions.",
    tools=get_adk_tools(),
)
```

`get_adk_tools()` runs at engine boot, after the MCP registry has connected to every server in `mcp_servers`, so every advertised tool is available to the agent without per-tool wiring. See [MCP Servers](/mcp-servers/overview) for the full transport reference.

## Session and memory services

ADK agents have two persistence layers: session services (conversation state) and memory services (long-term recall). The scaffolded `config.yaml` uses in-memory for both by default. See [Memory and sessions for ADK](/memory/adk) for backend options including Database (PostgreSQL) and Vertex AI.

<Warning>
  ADK does not support folder paths that contain spaces. Make sure your project directory path has no spaces.
</Warning>
